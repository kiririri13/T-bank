# T-Банк Loyalty Hub

Полноценное веб-приложение для единого раздела лояльности Т-Банка по данным кейса РадиоХак.  
Проект показывает персональную выгоду клиента: счета, кэшбэк, историю выплат, партнеров, достижения, прогноз и рекомендации экосистемы.

Приложение состоит из связанного frontend и backend, работает локально на `http://localhost:3000` и использует только пять исходных CSV-таблиц из датасета.

## Главное

| Блок | Что делает |
| --- | --- |
| Главная | Позволяет мгновенно выбрать клиента и открыть его личный раздел без почты и пароля. |
| Счета | Показывает все счета пользователя, баланс, кэшбэк и подробные выплаты по кнопке `Подробнее`. |
| Аналитика | Строит график выплат по месяцам, раскрывает конкретные даты начислений и сворачивает детализацию повторным кликом. |
| Прогноз | Рассчитывает ожидаемую выгоду на следующий месяц и на ближайшие 3 месяца. |
| Достижения | Показывает 6 прогресс-баров по заданным максимумам и общий средний прогресс. |
| Партнеры | Отображает доступные предложения, логотипы и кэшбэк партнеров из `Offers.csv`. |
| Экосистема | Показывает 3 подробные карточки продуктов Т-Банка с преимуществами и hover-анимацией. |

## Быстрый Запуск

```bash
npm start
```

После запуска откройте:

```text
http://localhost:3000
```

Если `npm` недоступен, можно запустить напрямую:

```bash
node server.js
```

На Windows также есть готовый файл:

```bat
start-server.cmd
```

Проект развернут на двух сервисах:

- Frontend на Cloudflare Pages: [https://tbank-loyalty-hub.pages.dev/](https://tbank-loyalty-hub.pages.dev/)

Для Render backend:

```text
Build Command: npm ci

Health Check Path: /api/health
```

Для Cloudflare Pages frontend:

```text
Build command: npm run build:pages
Build output directory: public
```

## Возможности Интерфейса

### Выбор Клиента

На стартовом экране сразу доступны все пользователи из `Users.csv`.  
Можно найти клиента по имени или `id` и открыть его персональный раздел одним кликом.

### Счета

Для каждого счета отображается:

- название программы лояльности;
- текущий баланс;
- сумма полученного кэшбэка и бонусов;
- кнопка `Подробнее`.

Поведение кнопки:

- первый клик раскрывает подробности;
- повторный клик по тому же счету сворачивает подробности;
- кнопка `Свернуть` внутри блока также закрывает детализацию.

### Аналитика

График показывает последние месяцы выплат.  
При клике по столбцу открываются конкретные даты начислений кэшбэка за выбранный месяц.  
Повторный клик по тому же столбцу сворачивает детализацию.

Вверху аналитики есть краткая сводка:

- сумма за период;
- среднее значение;
- лучший месяц.

### Достижения

Реализованы 6 достижений:

| Достижение | Максимум |
| --- | ---: |
| Получать кэшбэк несколько месяцев подряд | 12 |
| Иметь активные счета | 3 |
| Накопить кэшбэк | 50 000 |
| Хранить деньги на балансе | 1 000 000 |
| Накопить максимум кэшбэка за 1 месяц | 5 000 |
| Совершать операции | 100 |

Процент каждого progress bar считается от своего максимума.  
Общий прогресс в шапке считается как среднее значение всех шести прогрессов.

### Партнеры

До нажатия `Показать все` отображаются 8 доступных партнеров.  
После раскрытия показываются все доступные предложения для пользователя.  
Логотипы, описания, цвета и проценты кэшбэка берутся из `Offers.csv`.

### Экосистема

Раздел содержит 3 подробные карточки продуктов:

- Т-Мобайл;
- Т-Инвестиции;
- Т-Бизнес.

Каждая карточка содержит описание, потенциал выгоды, прогнозируемую прибавку в месяц, преимущества и кнопку `Подробнее`.  
При наведении карточка немного выдвигается вверх.

## Как Считается Прогноз

Прогноз на следующий месяц строится по последним 3 месяцам выплат:

```text
прогноз = среднее последних 3 месяцев + (последний месяц - первый месяц) × 0.18
```

Если динамика растет, прогноз немного повышается.  
Если динамика падает, прогноз становится осторожнее.  
Если истории выплат нет, прогноз равен `0`.

Прогноз на 3 месяца считается так:

```text
прогноз_на_3_месяца = прогноз_на_следующий_месяц × 3.08
```

## Обработка Ошибок

Приложение не должно крашиться при сбоях:

- сетевые ошибки `fetch` показываются понятным сообщением;
- битый JSON от сервера обрабатывается на фронтенде;
- неожиданные ошибки приложения перехватываются через `window.error` и `unhandledrejection`;
- backend возвращает JSON-ошибку `500` при непредвиденном сбое;
- некорректный URL возвращает `400`;
- некорректный логин возвращает `401`;
- отсутствующий пользователь возвращает `404`.

## API

| Метод | URL | Назначение |
| --- | --- | --- |
| `GET` | `/api/health` | Проверка сервера и списка CSV. |
| `GET` | `/api/users` | Список пользователей для стартового экрана. |
| `POST` | `/api/login` | Поиск пользователя по `id`, email или телефону. |
| `GET` | `/api/users/:id/dashboard` | Полный личный раздел пользователя. |

## Архитектура

### Backend

`server.js` отвечает за:

- чтение CSV;
- сбор персонального дашборда;
- расчет метрик, достижений и прогноза;
- фильтрацию партнеров;
- API;
- отдачу статических файлов frontend.

Backend написан на чистом Node.js без внешних зависимостей.

### Frontend

`public/app.js` отвечает за:

- выбор клиента;
- загрузку данных через API;
- отрисовку счетов, графика, партнеров, достижений и экосистемы;
- раскрытие и сворачивание интерактивных блоков;
- обработку ошибок.

`public/styles.css` отвечает за:

- темную и светлую темы;
- фирменную желто-черную визуальную систему;
- адаптивную сетку;
- кастомный скролл;
- hover-анимации карточек.
